本文整理自在北京大学计算中心未名一号高性能计算平台上安装 CESM 时的笔记，主要内容是 CESM 所需的基本环境的配置，以及对 CESM 配置文件的修改。

笔者全然不懂计算机知识，本文只能算是自己安装经验 + AI 指导的总结，如有不专业之处请见谅。

## 1. CESM 安装和检出

参考[官网教程](https://escomp.github.io/CESM/versions/cesm2.1/html/downloading_cesm.html)即可。按照其中的内容操作，一直到 `./manage_externals/checkout_externals`。

几个注意事项：

- 有时使用 `git` 命令需要翻墙，翻墙方法见下；
- **要在 data 节点安装**，login 节点没网。

**服务器翻墙**

这里的方法基于本地的 PKUWalless 节点和 Clash，如果读者不是 PKU 用户，可能需要根据自己的配置研究一下。[参考文章](https://zhuanlan.zhihu.com/p/18500712254)。

1. 打开本地 Clash，勾选 ☑️ "允许局域网连接"；
2. 在本地 terminal 输入：
   ```bash
   ssh -vvv -N -R 7890:localhost:7890 -p <远程服务器端口号> <username>@<server_ip>
   ```
   其中，因为大部分服务器默认端口是 22，`-p` 可以不设置。
3. 在服务器的 terminal 设置代理，复制 Clash 中的"复制终端代理命令"，粘贴到 terminal 里；
4. 使用完后取消代理：
   ```bash
   unset https_proxy
   unset http_proxy
   unset all_proxy
   ```

## 2. 环境配置（重中之重）

未名一号提供许多可用 module，但有些互相依赖的库之间版本不完全匹配，总是会报各种错误。于是，下面尝试手动安装全部所需的环境。参考[上交超算网站](https://docs.hpc.sjtu.edu.cn/app/engineeringscience/cesm.html)的配置，结合组内服务器实际安装经验，需要安装的内容如下：

```
gcc            : 7.5.0
HDF5           : 1.10.1
OpenBLAS       : 0.3.20
netcdf-c       : 4.4.1.1
netcdf-fortran : 4.4.1
parallel-netcdf: 1.9.0（不是必要，这里暂未安装）
zlib           : 1.2.10
```

### 2.1 安装 gcc

[清华开源镜像站](https://mirrors.tuna.tsinghua.edu.cn/gnu/gcc/)上有各种版本。不知为何，在服务器上直接 `wget` 总是 403，所以可以下载到本地再上传。

因为是从最基础的环境开始配置，一开始需要清空环境变量：

```bash
unset CPPFLAGS LDFLAGS LIBS CFLAGS CXXFLAGS FFLAGS FCFLAGS INCLUDE LIBRARY_PATH
```

进入 gcc 目录后，首先下载所依赖的库：

```bash
./contrib/download_prerequisites
```

然后创建 build 目录，进行 configure 和 make：

```bash
mkdir build && cd build
../configure \
    --prefix=$HOME/local/gcc-7.5.0 \
    --enable-languages=c,c++,fortran \
    --disable-multilib \
    --disable-bootstrap
make -j4
make install
```

安装成功后，写一个脚本配置环境变量：

```bash
vim ~/env_set.sh
```

写入以下内容：

```bash
# 编译器路径
export PATH=$HOME/local/gcc-7.5.0/bin:$PATH
export LD_LIBRARY_PATH=$HOME/local/gcc-7.5.0/lib64:$HOME/local/gcc-7.5.0/lib:$LD_LIBRARY_PATH

# 设置编译时使用的编译器
export CC=gcc
export CXX=g++
export FC=gfortran
export F77=gfortran

# 定义安装根目录（zlib、HDF5、netcdf 等库将统一安装到此处）
export PREFIX=$HOME/local/libs

# 让编译系统能找到公共库的头文件和库文件
export CPPFLAGS="-I$PREFIX/include"
export LDFLAGS="-L$PREFIX/lib"
```

然后执行：

```bash
source ~/env_set.sh
```

### 2.2 安装 zlib

```bash
wget https://www.zlib.net/fossils/zlib-1.2.10.tar.gz
tar -zxvf zlib-1.2.10.tar.gz
cd zlib-1.2.10
./configure --prefix=$PREFIX

```

### 2.3 安装 OpenBLAS

```bash
wget https://github.com/xianyi/OpenBLAS/archive/refs/tags/v0.3.20.tar.gz -O OpenBLAS-0.3.20.tar.gz
tar -xzf OpenBLAS-0.3.20.tar.gz
cd OpenBLAS-0.3.20
make -j4
make install PREFIX=$HOME/local/OpenBLAS-0.3.20
```

> **注**：OpenBLAS 独立安装目录，便于版本管理。若要与 CESM 连接，还需在 cime 中做额外配置，见下文。

```bash
wget https://github.com/Unidata/netcdf-fortran/archive/refs/tags/v4.4.1.tar.gz
tar -xzf v4.4.1.tar.gz
```

### 2.7 设置 perl，解决 XML::LibXML 问题

首先调整 PATH，让 `which perl` 指向系统 perl。注意检查 PATH 里是否混入了 conda，尽量移除，否则可能引起环境混乱：

```bash
export PATH=/usr/bin:/bin:$HOME/local/gcc-7.5.0/bin
```

以下步骤来自 DeepSeek：

```bash
mv ~/perl5 ~/perl5.bak   # 先备份
rm -rf ~/.cpanm
curl -L https://cpanmin.us | perl - -l ~/perl5 App::cpanminus
export LIBXML2_CFLAGS="-I$HOME/local/include/libxml2"
export LIBXML2_LIBS="-L$HOME/local/lib -lxml2"
export PKG_CONFIG_PATH="$HOME/local/lib/pkgconfig:$PKG_CONFIG_PATH"
export CC=gcc
export CXX=g++
~/perl5/bin/cpanm XML::LibXML
```

然后再次安装并测试：

```bash
curl -L https://cpanmin.us | perl - -l ~/perl5 App::cpanminus
# 测试
perl -MXML::LibXML -e 'print "XML::LibXML OK\n"'
```

### 2.8 安装 mpich

```bash
wget https://www.mpich.org/static/downloads/3.4.3/mpich-3.4.3.tar.gz
tar -xzf mpich-3.4.3.tar.gz
cd mpich-3.4.3
./configure --prefix=$HOME/local/mpich-3.4.3 \
```

---

这样，就完成了所有需要下载和配置的环境。都成功后，编写并 `source` 下面的脚本，在每次使用 CESM 创建 case 之前一键配好环境。

```bash
#!/bin/bash
# CESM 编译环境设置脚本
# 用法：source ~/cesm_env.sh

# -------------------- 基础根目录 --------------------
export CESM_ROOT=$HOME/local

# 统一库安装目录（zlib、HDF5、netcdf-c、netcdf-fortran 均安装于此）
export PREFIX=$CESM_ROOT/libs

# -------------------- 编译器（GCC 7.5.0）--------------------
export PATH=/usr/bin:$CESM_ROOT/gcc-7.5.0/bin:$PATH
export LD_LIBRARY_PATH=$CESM_ROOT/gcc-7.5.0/lib64:$CESM_ROOT/gcc-7.5.0/lib:$LD_LIBRARY_PATH

export CC=gcc
export CXX=g++
export FC=gfortran
export F77=gfortran

# -------------------- 统一库路径（HDF5、zlib、NetCDF 等）--------------------
export PATH=$PREFIX/bin:$PATH
export LD_LIBRARY_PATH=$PREFIX/lib:$LD_LIBRARY_PATH
export CPPFLAGS="-I$PREFIX/include"
export LDFLAGS="-L$PREFIX/lib"

# CESM 需要通过 $NETCDF 变量定位 NetCDF
export NETCDF=$PREFIX

# -------------------- OpenBLAS --------------------
export LD_LIBRARY_PATH=$CESM_ROOT/OpenBLAS-0.3.20/lib:$LD_LIBRARY_PATH

# -------------------- MPI（mpich 3.4.3）--------------------
export PATH=$CESM_ROOT/mpich-3.4.3/bin:$PATH
export LD_LIBRARY_PATH=$CESM_ROOT/mpich-3.4.3/lib:$LD_LIBRARY_PATH

if command -v mpirun &>/dev/null; then
    echo "检测到 MPI 环境：$(which mpirun)"
    export MPICC=mpicc
    export MPIFC=mpif90
    export MPIF77=mpif77
else
    echo "警告：未找到 MPI 命令，如果使用并行功能请安装 MPI。"
fi

# -------------------- Perl / XML::LibXML --------------------
export PERL5LIB=$HOME/perl5/lib/perl5:$PERL5LIB
export LIBXML2_CFLAGS="-I$PREFIX/include/libxml2"
export LIBXML2_LIBS="-L$PREFIX/lib -lxml2"
export PKG_CONFIG_PATH="$PREFIX/lib/pkgconfig:$PKG_CONFIG_PATH"

# -------------------- 环境检查 --------------------
echo "CESM 编译环境已加载。"
echo "GCC 版本：$(gcc --version | head -n1)"
echo "NetCDF 路径：$NETCDF"
echo "CPPFLAGS：$CPPFLAGS"
echo "LDFLAGS：$LDFLAGS"
perl -MXML::LibXML -e 'print "XML::LibXML OK\n"'
```

## 3. CESM cime 设置

cime 是一个独立软件包，可以创建和配置 CESM case。详细介绍和教程可参考[说明文档网站](https://esmci.github.io/cime/versions/maint-5.6/html/what_cime/index.html)。这里从实用主义角度，列出成功运行 CESM 需要作哪些修改。更灵活的修改可以自行学习和尝试。

### 3.1 修改 machine 配置

创建新 case 时需要指定 machine 名称，未名一号是 centos7-linux，但是在 `$CODE/cime/config/cesm/machines/` 中的 `config_machine.xml` 中 centos7-linux 是默认配置，需要手动添加一些内容（也可以按照 template 直接自己写一个）。修改的部分如下。

> **注**：xml 文件的 `<!--` 和 `-->` 之间为注释内容，下文 `#` 只是方便阅读。

```xml
<machine MACH="centos7-linux">

    # 开头部分不用改

    # 下面这几行要改，是输入输出数据和运行目录的默认位置。
    # 在组里服务器中要挪到 data 节点，否则会默认建立在 home 下，后面会占用大量空间。
    <CIME_OUTPUT_ROOT>$ENV{HOME}/CESM/cesm_data/scratch</CIME_OUTPUT_ROOT>
    <DIN_LOC_ROOT>$ENV{HOME}/CESM/cesm_data/inputdata</DIN_LOC_ROOT>
    <DIN_LOC_ROOT_CLMFORC>$ENV{HOME}/CESM/cesm_data/inputdata/lmwg</DIN_LOC_ROOT_CLMFORC>
    <DOUT_S_ROOT>$ENV{HOME}/CESM/cesm_data/archive/$CASE</DOUT_S_ROOT>
    <BASELINE_ROOT>$ENV{HOME}/CESM/cesm_data/cesm_baselines</BASELINE_ROOT>
    <CCSM_CPRNC>$ENV{HOME}/CESM/cesm_data/tools/cime/tools/cprnc/cprnc</CCSM_CPRNC>

    # 这里要改成 slurm
    <BATCH_SYSTEM>slurm</BATCH_SYSTEM>

    # 这里的节点数根据服务器情况改，或者创建完 case 再改
    <MAX_TASKS_PER_NODE>128</MAX_TASKS_PER_NODE>
    <MAX_MPITASKS_PER_NODE>128</MAX_MPITASKS_PER_NODE>

    # 针对未名一号，需要修改下面的 module 配置
    <module_system type="module" allow_error="true">
        <!--
        <init_path lang="perl">/usr/share/Modules/init/perl.pm</init_path>
        <init_path lang="python">/usr/share/Modules/init/python.py</init_path>
        <init_path lang="csh">/usr/share/Modules/init/csh</init_path>
        <init_path lang="sh">/usr/share/Modules/init/sh</init_path>
        <cmd_path lang="perl">/usr/bin/modulecmd perl</cmd_path>
        <cmd_path lang="python">/usr/bin/modulecmd python</cmd_path>
        -->
        <init_path lang="perl">/etc/profile.d/module.sh</init_path>
        <init_path lang="python">/etc/profile.d/module.sh</init_path>
        <init_path lang="csh">/etc/profile.d/module.csh</init_path>
        <init_path lang="sh">/etc/profile.d/module.sh</init_path>
        <cmd_path lang="perl">module</cmd_path>
        <cmd_path lang="python">module</cmd_path>
        <cmd_path lang="sh">module</cmd_path>
        <cmd_path lang="csh">module</cmd_path>
        # 未名要先加载 cmake，经测试这个版本和此前安装的内容都兼容
        <modules compiler="gnu">
            <command name="purge"/>
            <command name="load">cmake/3.16.0</command>
        </modules>

    # 把下面这段注释掉，防止找到版本不同的环境
    <!--
    <modules compiler="gnu">
        <command name="load">compiler/gnu/8.2.0</command>
        <command name="load">mpi/3.3/gcc-8.2.0</command>
        <command name="load">tool/netcdf/4.6.1/gcc-8.1.0</command>
    </modules>
    -->

    <environment_variables>
        <env name="OMP_STACKSIZE">256M</env>
        # 这里加上 netcdf 的路径
        <env name="NETCDF_PATH">$ENV{HOME}/local/libs</env>
    </environment_variables>

</machine>
```

### 3.2 修改 compiler 配置

组里服务器和未名一号都是修改 `$CODE/cime/config/cesm/machines/config_compiler.xml` 的 `<compiler COMPILER="gnu">` 部分，具体修改如下。

```xml
<compiler COMPILER="gnu">
    <CFLAGS>
        <base> -std=gnu99 </base>
        <append compile_threaded="true"> -fopenmp </append>
        <append DEBUG="TRUE"> -g -Wall -Og -fbacktrace -ffpe-trap=invalid,zero,overflow -fcheck=bounds </append>
        <append DEBUG="FALSE"> -O </append>
    </CFLAGS>
    <!-- 这里加了 netcdf 路径 -->
    <NETCDF_PATH>$ENV{HOME}/local/libs</NETCDF_PATH>

    <!-- 中间不用改 -->

    <FREEFLAGS>
        <base> -ffree-form </base>
    </FREEFLAGS>
    <!-- 下面添加 netcdf 路径和 OpenBLAS 路径 -->
    <SLIBS>
        <append>-L$(NETCDF_PATH)/lib -lnetcdff -lnetcdf -L$(HOME)/local/OpenBLAS-0.3.20/lib -lopenblas</append>
    </SLIBS>

</compiler>
```

其中，OpenBLAS 部分的路径需要确认，运行以下命令查看哪个目录下有实际文件：

```bash
ls -l ~/local/OpenBLAS-0.3.20/lib/libopenblas*
ls -l ~/local/OpenBLAS-0.3.20/lib64/libopenblas*
```

将有内容的路径填入 `SLIBS` 中。

### 3.3 修改 batch 配置

在 `$CODE/cime/config/cesm/machines/config_batch.xml` 中新建一个类别，如下：

```xml
<batch_system MACH="centos7-linux" type="slurm">
    <batch_submit>sbatch</batch_submit>
    <!--
    <batch_query per_job_arg="-j">squeue</batch_query>
    -->
    <batch_cancel>scancel</batch_cancel>
    <batch_directive>#SBATCH</batch_directive>
    <jobid_pattern>(\d+)$</jobid_pattern>
    <depend_string> --dependency=afterok:jobid</depend_string>
    <depend_allow_string> --dependency=afterany:jobid</depend_allow_string>
    <depend_separator>,</depend_separator>
    <walltime_format>%H:%M:%S</walltime_format>
    <batch_mail_flag>--mail-user</batch_mail_flag>
    <batch_mail_type_flag>--mail-type</batch_mail_type_flag>
    <batch_mail_type>none, all, begin, end, fail</batch_mail_type>
    <directives>
        <directive> --job-name={{ job_id }}</directive>
        <directive> --nodes={{ num_nodes }}</directive>
        <directive> --ntasks-per-node={{ tasks_per_node }}</directive>
        <directive> --output={{ job_id }}.out</directive>
        <directive> --partition=C032M0128G</directive>
        <directive> --qos=normal</directive>
    </directives>
    <queues>
        <queue walltimemax="48:00:00" nodemin="1" nodemax="20" default="true">normal</queue>
    </queues>
</batch_system>
```

其中 `walltimemax`、`nodemin`、`nodemax` 根据服务器情况确定，分区（`--partition`）可根据服务器说明文档修改。

### 3.4 未名一号的特殊配置

未名的 login 节点的 module 只是一个函数，`modulecmd` 不能被直接调用，所以在 login 节点执行 setup 和 build 会报错（而在 data 节点就没有这个问题）。令人无奈的是，在 login 节点执行提交命令也会遇到这个报错。

此外，login 节点也没有 cmake，需要自行 load cmake，可以通过 `module avail cmake` 查看可用 module，然后写到下面的 xml 文件中。

因此，在未名的 `$CASEROOT` 下要修改 `env_mach_specific.xml` 文件，改成如下内容：

```xml
<module_system allow_error="true" type="module">
    <init_path lang="perl">/etc/profile.d/module.sh</init_path>
    <init_path lang="python">/etc/profile.d/module.sh</init_path>
    <init_path lang="csh">/etc/profile.d/module.csh</init_path>
    <init_path lang="sh">/etc/profile.d/module.sh</init_path>
    <!--
    <init_path lang="perl">/usr/share/Modules/init/perl.pm</init_path>
    <init_path lang="python">/usr/share/Modules/init/python.py</init_path>
    <init_path lang="csh">/usr/share/Modules/init/csh</init_path>
    <init_path lang="sh">/usr/share/Modules/init/sh</init_path>
    -->
    <!--
    <cmd_path lang="perl">/usr/bin/modulecmd perl</cmd_path>
    <cmd_path lang="python">/usr/bin/modulecmd python</cmd_path>
    -->
    <cmd_path lang="perl">module</cmd_path>
    <cmd_path lang="python">module</cmd_path>
    <cmd_path lang="sh">module</cmd_path>
    <cmd_path lang="csh">module</cmd_path>
    <modules>
        <command name="purge"/>
        <command name="load">cmake/3.16.0</command>
    </modules>
</module_system>
```

更一劳永逸地，在 3.1 节"修改 machine 配置"中作上述修改，此后新建的 case 都会沿用新配置。

此外，任务执行原本是 `mpiexec -np xxx`，在未名上需要改为 `mpiexec -n xxx`，可以在 `env_mach_specific.xml` 中修改，亦可在 machine 配置中修改。
